## 3. Apply

The apply was executed on 2026-11-18. For a rebuild, apply the same commands.

The first apply creates the infrastructure but not the images. Build and push them:

```bash
PROJECT=ai-dataops-demo-jma
REGION=us-central1
REPO=${REGION}-docker.pkg.dev/${PROJECT}/ai-dataops

# Option A: Docker locally
docker build --build-arg UV_EXTRAS="--extra ai --extra gcp" -t ${REPO}/job:v6 .
docker push ${REPO}/job:v6
docker build --build-arg UV_EXTRAS="--extra dashboard" -t ${REPO}/dashboard:v5 .
docker push ${REPO}/dashboard:v5

# Option B: Cloud Build / Kaniko (used here, no Docker socket)
gcloud builds submit --project ${PROJECT} \
  --service-account projects/${PROJECT}/serviceAccounts/dataops-build@${PROJECT}.iam.gserviceaccount.com \
  --config cloudbuild.yaml \
  --substitutions=_IMAGE=${REPO}/job:v6,_EXTRAS="--extra ai --extra gcp" .
gcloud builds submit --project ${PROJECT} \
  --service-account projects/${PROJECT}/serviceAccounts/dataops-build@${PROJECT}.iam.gserviceaccount.com \
  --config cloudbuild.yaml \
  --substitutions=_IMAGE=${REPO}/dashboard:v5,_EXTRAS="--extra dashboard" .

# Roll out (or pass job_image/dashboard_image to Terraform and apply)
gcloud run jobs update dataops-job --region ${REGION} --image ${REPO}/job:v6
gcloud run services update dataops-dashboard --region ${REGION} --image ${REPO}/dashboard:v5
```

## 4. Seed the demo history

The job creates tables at runtime (BigQuery DDL is generated by the application) and seeds
metadata. Seed 45 labelled days, then export the serving snapshot:

```bash
gcloud run jobs execute dataops-job --region us-central1 --wait \
  --args="demo","--days","45","--volume","1500"

# The seed can take 1-2 hours in BigQuery. If it is interrupted, re-run the daily job;
# partitions are replaced per logical date, so replays are safe.
```

Diagnose pending incidents (the daily job also does this for the current date):

```bash
gcloud run jobs execute dataops-job --region us-central1 --wait \
  --args="diagnose","--provider","vertex","--limit","50"
```

Then run one daily cycle to confirm the scheduler path and publish the snapshot:

```bash
gcloud run jobs execute dataops-job --region us-central1 --wait
```

The daily job runs `run-daily` and publishes
`gs://ai-dataops-demo-jma-ai-dataops-serving/serving/snapshot.json`.
The dashboard reads that URI; no BigQuery access from the public service.

## 5. Operate

```bash
# job status and logs
gcloud run jobs executions list --job dataops-job --region us-central1 --limit 5
gcloud logging read 'resource.type="cloud_run_job" AND resource.labels.job_name="dataops-job"' \
  --project ai-dataops-demo-jma --limit 50 --format json

# manual diagnosis for a date
gcloud run jobs execute dataops-job --region us-central1 --wait \
  --args="diagnose","--date","2026-11-18","--provider","vertex"

# snapshot refresh
gcloud run jobs execute dataops-job --region us-central1 --wait \
  --args="export-serving"

# dashboard URL
terraform output -raw dashboard_url
```

Alerts and guardrails:

- Budget alerts at 50/80/100% of US$ 5 (if configured).
- Application-level diagnosis budget US$ 2/month; requests beyond it are recorded as
  `skipped_budget`, never silently dropped.
- Cloud Run max instances = 2; dashboard reads a JSON object, not BigQuery.
- BigQuery tables are partitioned with 400-day expiration; `require_partition_filter` on the
  high-volume tables.

## 6. Cost controls

- Scale to zero everywhere; one scheduler job; no minimum instances.
- Batch loads for demo rows (free); `MERGE` only for small metadata/fact tables.
- Gemini calls only for medium+ incidents, deduplicated by evidence hash.
- Snapshot keeps page views away from BigQuery.

If the demo is not being shown, pause the scheduler:

```bash
gcloud scheduler jobs pause dataops-daily --location us-central1
```
